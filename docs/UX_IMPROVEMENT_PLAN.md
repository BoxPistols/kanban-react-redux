# UI/UX 要因分析と改善方針 — Trello 比較

> 「Trello より使い勝手が劣り、使う気にならない」という評価に対する徹底的な要因分析と、
> フェーズ別の改善ロードマップ。すべての指摘にコード上の根拠 (ファイル:行) を付す。

> **実装状況 (2026-07):** Phase 0 全項目 / Phase 1 全項目 / Phase 2 の 1〜4 /
> Phase 3 の 2〜5 を実装済み。未着手: 説明の Markdown 対応・期限の時刻指定 (Phase 2)、
> ボードスイッチャー刷新・画像の Storage 移行 (Phase 3)、Phase 4 全項目。
> 行番号の参照は実装前のコードに基づく。

## 結論サマリ

使う気にならない最大の要因は **見た目ではなく「操作の手応え」の欠落** にある。
カンバンの体験は「①カードを素早く作る → ②ドラッグで動かす → ③開いて編集する」の
3 動作がほぼすべてであり、本アプリはその 3 つ全部に構造的な欠陥を抱えている。

| # | 領域 | 致命度 | 一言でいうと |
|---|------|--------|--------------|
| 1 | ドラッグ&ドロップ | ★★★ | ドロップするまで何も起きず、ドロップ後は一瞬巻き戻る |
| 2 | カード作成 | ★★★ | Enter で追加できない・連続入力できない・追加位置が視界外 |
| 3 | 詳細編集 | ★★★ | 自動保存がなく、ESC/外側クリックで編集内容が無警告で全損 |
| 4 | 情報設計 | ★★☆ | ラベル名が読めない・ボード切替が `<select>`・フィルタ状態が不可視 |
| 5 | フィードバック | ★★☆ | 失敗が無言、成功も無言。Undo なし、confirm() 依存 |
| 6 | 性能・信頼性 | ★★☆ | 楽観的更新なし・全カード購読・画像 base64 保存 |

Trello が 15 年かけて磨いたのは機能の数ではなく **「操作 → 即時反映 → 失敗時だけ知らせる」**
というフィードバックループの速さである。改善方針もこの順で組む。

---

## 1. 要因分析

### 1.1 ドラッグ&ドロップ — カンバンの心臓部が「重く・鈍く・不誠実」

**(a) ドラッグ中のライブプレビューがない(最重要)**
`App.tsx` の `DndContext` には `onDragStart` / `onDragEnd` しかなく、**`onDragOver` が未実装**
(`src/App.tsx:357`)。dnd-kit で列またぎの並べ替えを行う場合、`onDragOver` でドラッグ中に
カードを仮移動させるのが定石だが、それがないため:

- 列をまたぐドラッグでは、**ドロップするまで挿入先のカードが 1px も避けない**。
  どこに入るのか事前に分からず、「置いてみて外れたらやり直す」操作になる。
- Trello はドラッグした瞬間に灰色のプレースホルダーが現れ、通過中の列でカードが
  リアルタイムに割れて挿入位置を示す。この差が「安っぽさ」の体感の大半を占める。

**(b) 楽観的更新がなく、ドロップ後にカードが巻き戻る**
`kanbanStore.reorderCards` は Firebase モードで `writeBatch → commit` を await し、
ローカル state を先に更新しない (`src/store/kanbanStore.ts:326-371`)。反映は Firestore の
`onSnapshot` 経由なので、**ドロップ → dnd-kit の transform が解除されて元の位置に
スナップバック → 数百 ms 後にサーバー反映で正しい位置へジャンプ**という二段挙動になる。
Trello は即時にローカル反映し、同期は裏で行い、失敗時のみロールバックする。

**(c) ドラッグの「掴んだ感」が遅い**
`PointerSensor` の activationConstraint が `distance: 8` + `delay: 100` + `tolerance: 5`
(`src/App.tsx:76-84`)。distance と delay の併用でドラッグ開始が体感的にワンテンポ遅れる。
クリック(詳細を開く)との誤爆防止なら `distance: 4〜5` 単独で十分。

**(d) カード全体が `touch-action: none`**
カードコンテナに `{...listeners}` を直接展開し、CSS で `touch-action: none`
(`src/Card.tsx:83`, `src/Card.tsx:176`)。**モバイルではカードに触れた指でカラムを
縦スクロールできない**。カードが敷き詰まった列はスクロール不能地帯になる。

**(e) レーン(カラム)をボード上で直接ドラッグできない**
レーンの並べ替え・改名・色変更は「レーン管理」モーダルの中でしかできない
(`src/App.tsx:392-400`, `src/ColumnManager.tsx`)。Trello はリストのヘッダーを掴んで
その場で並べ替え、タイトルをクリックしてその場で改名できる。
「ボード上で完結する操作」を「設定モーダル」に退避させた分だけ操作距離が伸びている。

**(f) フィルタ中はドラッグが無言で無効**
検索・ラベルフィルタ中は `handleDragEnd` が黙って `return` する (`src/App.tsx:219`)。
order 破壊防止(監査 C7)という実装都合は正しいが、ユーザーには
**「ドラッグが壊れている」ようにしか見えない**。ドラッグ開始時に禁止を予告するか、
少なくともトーストで理由を伝える必要がある。

**(g) その他**
- `collisionDetection` 未指定(デフォルトの rectIntersection)。縦長カードや空列付近で
  当たり判定が不安定になりやすい。
- `KeyboardSensor` 未登録でキーボードによる並べ替え不可(a11y)。
- 列またぎ移動時に移動元カラムの order を再採番しない (`src/App.tsx:252-278`) ため
  order に穴が空き続ける(末尾追加は max+1 で回避済みだが、根本は残る)。

### 1.2 カード作成 — 最頻操作なのに打鍵とクリックが多すぎる

**(a) Enter で追加できない**
`InputForm` は textarea で、確定は **Cmd/Ctrl+Enter のみ**。素の Enter は改行
(`src/InputForm.tsx:46-56`)。Trello は「Enter=追加」で、カード名に改行が要る場面は
ほぼない。タイトル入力欄なのに note 用の UI になっている。

**(b) 連続入力できない**
追加が確定すると `setInputMode(false)` でフォームが閉じる (`src/Column.tsx:41-47`)。
5 枚書き出したいとき、毎回列ヘッダーの小さな「+」を押し直す。
Trello はコンポーザーが開いたまま次のカードを打てる(離脱するまで閉じない)。

**(c) 入力欄の位置と追加位置が逆**
フォームは列の**最上部**に出る (`src/Column.tsx:109`) が、`addCard` は
`maxOrder + 1` で**末尾**に追加する (`src/store/kanbanStore.ts:135-136`)。
長い列では「追加したはずのカードが視界の外」になる。Trello は
「リスト末尾の + カードを追加」と「追加先=そこ」が一致している。

**(d) 文言の言語が混在**
プレースホルダー `Enter a note (⌘+Enter to submit)`、ボタン `Add` / `Cancel`
(`src/InputForm.tsx:43`, `121-127`)だけが英語で、アプリの他は日本語。
CLAUDE.md の禁止パターン「ハードコードされた文字列(i18n 対象はすべて定数化)」にも抵触。

**(e) 追加も Firestore 往復待ち**
`addCard` も楽観的更新なし (`src/store/kanbanStore.ts:151-155`)。回線次第で
「打った → 一拍おいて出現」となり、連続入力のリズムを壊す。

### 1.3 カード詳細編集 — データ損失リスクが最も深刻

**(a) 自動保存がなく、閉じると全変更が無警告で破棄される**
`CardDetailModal` は title/description/labels/checklist/期限/色/画像をすべてローカル
state に溜め、「保存」ボタンでのみ `updateCard` する (`src/CardDetailModal.tsx:229-256`)。
一方 `BaseModal` は **ESC とオーバーレイクリックの両方で即 `onClose`**
(`src/BaseModal.tsx:97-98`, `132`)。dirty チェックも確認ダイアログもないため、
説明を 10 分書いて外側を誤クリックすると**全部消える**。
Trello はフィールド単位の自動保存で、この事故が構造的に起きない。
「使う気にならない」評価の引き金として最有力の欠陥。

**(b) `text` と `title` の二重構造**
作成時は `text`、モーダルでは `title` を編集し、表示は `card.title || card.text`
(`src/Card.tsx:58`)。一度 title を保存すると text は不可視のまま残存し、
検索は text にもヒットする (`src/App.tsx:94`) ため「見えない文字列で検索に当たる」
不可解な挙動になる。

**(c) カード面でのインライン編集がない**
タイトルの修正だけでもモーダルを開いて保存する必要がある。Trello はカード上で
直接クイック編集できる。

**(d) 削除ボタンがカード面に常設 + `window.confirm`**
hover で現れるゴミ箱がカード右上に (`src/Card.tsx:152`, `319-350`)。詳細を開く・
ドラッグするの近傍に破壊的操作が同居し、確認はネイティブ `confirm()`
(`src/Card.tsx:42`)。ゴミ箱(復元可能)がある (`src/store/trashStore.ts`) のに
confirm を挟むのは二重に保守的で、しかも見た目が最も安っぽい部分。
Trello 流は「即アーカイブ + Undo トースト」。

**(e) 機能面の不在**
コメント/アクティビティ履歴、モーダルからの列・ボード移動、担当者、
期限の時刻指定、説明の Markdown。特に「このカードを別レーンへ」がモーダル内で
できないのは、D&D が上記の通り不自由なだけに痛い。

### 1.4 情報設計・ナビゲーション

**(a) カード上のラベル名が物理的に読めない**
`LabelBadge` は高さ 6px・幅 40px 固定・`font-size: 0` (`src/Card.tsx:214-221`)。
名前をレンダリングしているのに見えず、title 属性もなく、hover でも分からない。
Trello は色バーをクリックすると名前表示に切り替わる(その状態を記憶する)。

**(b) ボード切替がネイティブ `<select>`**
`src/BoardSelector.tsx:40-51`。ボードの色・説明・最終更新が見えず、スター/最近使った順も
ない。Trello の「ボード」体験(タイル一覧・背景プレビュー・スター)との落差が大きい。
また `board.color` は選択できるのに **24px の丸ポチにしか使われず** (`BoardSelector.tsx:37-39`)、
ボード背景に反映されない。「自分の場所」感が出ない。

**(c) フィルタ状態が不可視**
検索・ラベルフィルタ適用中であることを示すバーがなく、ヒット件数も出ない。
0 件でも空のカラムが並ぶだけ。しかもフィルタ中は D&D 無効(1.1f)。
「なにかおかしいが理由が分からない」状態を自ら作っている。

**(d) フィルタ用ラベルチップがドラッグでボードデータを書き換える**
ヘッダーのフィルタチップは 5px 動かすと並べ替えモードになり、**ボードのラベル順を
永続変更する** (`src/CardFilter.tsx:95-110`)。フィルタ(読み取り)UI に編集作用が同居し、
クリックとドラッグが誤爆する。`cursor: move` (`CardFilter.tsx:243`) でフィルタなのか
並べ替えなのか意図も曖昧。

**(e) デフォルト 6 レーンは多すぎる**
`DEFAULT_COLUMNS` は Backlog/TODO/Now/Doing/Waiting/Done の 6 本
(`src/types/index.ts:5-12`)。1 列 340px なので初期状態で約 2,100px、
ラップトップでも初見から横スクロールを強制される。Trello の新規ボードは 3 列。
「Now と Doing の違い」を新規ユーザーに考えさせる認知コストも高い。

**(f) 空ボード・オンボーディングが弱い**
初期状態の導線は「ヘッダーの + ボードから作成できます」というテキストのみ
(`src/App.tsx:364-373`)。カード 0 の列にも「ここに追加」の受け皿がない。

### 1.5 フィードバック・マイクロインタラクション

- store の `error` は set されるが、**トースト等での表示系がない**
  (BlockerWarning は接続ブロック専用)。保存失敗・並べ替え失敗はすべて無言。
- 成功も無言(追加・保存・削除にスナックバックなし)。削除だけ `confirm()`。
- **Undo が存在しない**(移動・編集・並べ替え)。ゴミ箱は削除のみカバー。
- ショートカットは Cmd+K(検索)のみ (`src/App.tsx:192-205`)。Trello の
  n(新規カード)/ f(フィルタ)/ x(フィルタ解除)/ 矢印ナビ相当がない。
- 削除・ログアウトが `window.confirm` (`src/Card.tsx:42`, `src/Header.tsx:34`) で
  世界観が崩れる。

### 1.6 性能・信頼性(UX に直結するもの)

- `subscribeToCards` は **`where('boardId'==...)` を付けず全カードを購読**し、
  クライアント側で filter (`src/store/kanbanStore.ts:400-429`)。ボードが増えるほど
  転送量・再描画とも悪化し、切替も重くなる。
- 画像を **base64 のままカードドキュメントに保存** (`src/CardDetailModal.tsx:206-219`)。
  Firestore の 1MB/doc 制限に容易に達し、「カードの更新に失敗しました」(無言に近い)
  で保存不能になる。5MB 制限チェックは base64 化前のファイルサイズなので防げない。
- テーマは各コンポーネントが `getTheme(isDarkMode)` を呼び `$theme` を全 styled に
  バケツリレー。ThemeProvider 不使用で、全カードがテーマ変更時に再レンダリング。

## 2. 改善方針(フェーズ別ロードマップ)

原則: **「操作 → 即時反映 → 失敗時だけ通知」** をすべての操作で成立させる。
新機能の追加より先に、既存 3 動作(作る・動かす・編集する)の手応えを直す。

### Phase 0 — 即効修正(1〜2 日、各数十行)

| 施策 | 対象 | 内容 |
|------|------|------|
| P0-1 | InputForm | Enter=追加(IME 対応済みの isComposing を流用)、Shift+Enter=改行 |
| P0-2 | Column | 追加後もコンポーザーを開いたままにして連続入力対応。フォームを列末尾へ移設し、追加時に末尾へスクロール |
| P0-3 | InputForm | 文言を日本語化し constants へ(「カードを追加」「キャンセル」) |
| P0-4 | App | activationConstraint を `{ distance: 5 }` のみに(delay 撤廃) |
| P0-5 | Card | LabelBadge を高さ 16px+ラベル名表示(または title 属性+クリックで展開トグル) |
| P0-6 | App/Toast | 簡易トースト基盤を追加し、フィルタ中ドラッグ時に「フィルタ中は並べ替えできません」を表示。store.error もトーストへ |
| P0-7 | 全体 | `window.confirm` 廃止。削除は即ゴミ箱行き+「削除しました [元に戻す]」トースト |

### Phase 1 — D&D の作り直し(3〜5 日) ★体感が最も変わる

1. **楽観的更新**: `reorderCards` / `moveCard` / `addCard` で先にローカル state を
   更新してから永続化。失敗時は元 state に戻し、トーストで通知。
   (onSnapshot との整合は「ローカル更新 → snapshot 上書き」で自然収束する)
2. **`onDragOver` 実装**: ドラッグ中に列またぎの仮移動を行い、挿入位置を
   リアルタイム表示。`collisionDetection: closestCorners` に変更。
   ドロップ先には点線プレースホルダーを描画。
3. **列またぎ時に両カラムを再採番**して order の穴を解消。
4. **レーン自体の D&D**: Column ヘッダーを `useSortable` 化し、ボード上で直接
   並べ替え。レーン名はヘッダーのダブルクリックでインライン改名。
5. **モバイル**: `TouchSensor`(delay 200ms)+ `PointerSensor` の併用にし、
   カードの `touch-action: none` を `manipulation` へ。指スクロールを取り戻す。
6. `KeyboardSensor` + アナウンス(a11y)。

### Phase 2 — 編集体験(3〜5 日) ★データ損失の根絶

1. **CardDetailModal の自動保存化**: フィールド単位で blur / debounce(500ms)保存。
   「保存/キャンセル」フッターを撤去(Trello 同等)。
   移行が大きい場合の暫定策: dirty 時の ESC・外側クリックに確認ダイアログ。
2. **`text`/`title` の一本化**: title に片寄せするマイグレーション
   (読み込み時に `title ?? text` を title へ、text は description 側へ退避)。
3. **カードのインライン編集**: カード面のクイック編集(鉛筆 hover →その場で
   タイトル編集)。
4. モーダルに**「移動」**(レーン/ボード選択)と**「ゴミ箱へ」**を追加し、
   カード面の常設削除ボタンは撤去(または hover メニューに集約)。
5. 説明の Markdown 対応(既存 LinkedText と統合)。期限に時刻+「完了」チェック。

### Phase 3 — 情報設計(1 週間)

1. **ボードスイッチャー刷新**: `<select>` → ポップオーバー(色タイル・説明・
   スター・最近使った順)。`board.color` をボード背景(MainArea)へ反映。
2. **フィルタバー**: フィルタ適用中は列ヘッダー下に「N 件を表示中 / クリア」を
   常設表示。ヒット 0 の列は「該当なし」を表示。
3. フィルタチップの**並べ替え機能を BoardModal 側へ移動**し、ヘッダーの
   チップはクリック(トグル)専用に。
4. **デフォルトレーンを 3 本**(TODO / Doing / Done)へ。既存ボードは不変。
5. Firestore クエリに `where('boardId', '==', boardId)` を追加(複合 index 定義込み)。
6. 画像添付を **Firebase Storage** へ移行(localStorage モードは現行 dataUrl 継続、
   サイズ合計に上限とエラー表示)。

### Phase 4 — 差別化・仕上げ(継続)

- 操作 Undo スタック(移動・編集・削除を Cmd+Z)
- ショートカット体系(n=カード追加 / f=検索 / x=フィルタ解除 / 矢印+Enter ナビ)
- WIP リミットとレーン集計(枚数/期限切れ数をヘッダーに)
- ThemeProvider 化と `$theme` バケツリレーの解消(再レンダリング削減)
- テンプレートボード、カードのコピー/リンク

### 実施順序の根拠

- Phase 0+1 で「触ったときの気持ちよさ」が Trello 比 8 割まで戻る。
  ここを飛ばして機能を足しても評価は変わらない。
- Phase 2 は唯一の**データ損失級**欠陥の除去であり、信頼の回復に必須。
- Phase 3 以降は「毎日開きたくなるか」の領域。効果はあるが 0〜2 の後で良い。

## 3. 成功指標(効果測定)

| 指標 | 現状 | 目標 |
|------|------|------|
| カード 1 枚追加の操作数 | クリック→入力→Cmd+Enter(フォーム閉じる) | 入力→Enter(連続入力可) |
| D&D 時の視覚フィードバック | ドロップまでなし+巻き戻り | 掴んだ瞬間からプレースホルダー、ドロップ即確定 |
| 編集内容の消失経路 | ESC / 外側クリック / × の 3 経路 | 0(自動保存) |
| 操作失敗の可視性 | ほぼ無言 | 全操作でトースト+Undo |
| 初期表示の横スクロール | 6 レーン ≒ 2,100px | 3 レーンで主要画面に収まる |
